# v0.14.0 Engineering Plan — Real-Repo Precision & Verification Leads

> **Status**: Phase M1 in progress on branch `feat/v0.14.0-precision` (base `main`, package version remains `0.13.0` during development).  
> **Scope discipline**: Preserve existing static-only evidence contracts (`exact` / `import-scoped` / `name-only`), never invent confidence probabilities, never persist source bodies in index caches, never parse third-party `node_modules` / `oh_modules` sources, and never execute candidate tests automatically.

---

## 1. Evidence & Contract Guardrails

1. **Deterministic resolution grading**: Keep `exact` / `import-scoped` / `name-only` intact. Add deterministic `via` metadata (e.g. `tsconfig-path`, `oh-package`, `package-exports`, `reexport(2)`, `tsconfig-path+reexport(1)`) without fabricating probabilities or numeric confidence scores.
2. **Strict ambiguity downgrade**: When a wildcard path alias or conditional export matches multiple distinct indexed files, forbid guessing: downgrade the relation to `import-scoped`, mark `ambiguousAlias: true`, and surface `ambiguous-alias` in `EvidenceSummary.gaps` and `ReviewBrief.gaps`.
3. **Bounded re-export traversal**: Traverse `export { ... } from` and `export * from` up to `MAX_REEXPORT_DEPTH = 3` using a cycle-safe `visited` set. Named re-export chains with a single unambiguous target may retain `exact`; `export * from` chains always stay `import-scoped` (never elevated to `exact`).
4. **No source body persistence**: Index cache files under `.dsh-code-index/` store only normalized resolution metadata (`configFiles` paths/mtimes, `tsConfigs`, `packageExports`, `ohPackages`) alongside existing symbol/import/call records—never source file contents or raw config text.

### 2.2 Cache Schema Upgrade (`schemaVersion: 4 -> 5`)

- Note: `REPO_INDEX_SCHEMA_VERSION` is already `4` (introduced in `v0.10.2` for Rust signatures). M1 bumps `REPO_INDEX_SCHEMA_VERSION` to `5`.
- **Automatic invalidation**: `loadIndex()` rejects any on-disk cache where `parsed.schemaVersion !== 5` (`null` return), causing `buildIndexWithCache()` to rebuild cleanly at the same cache path.
- **Persisted shape (`RepoIndex.resolution`)**:
  - `configFiles`: sorted array of `{ path, mtimeMs }` covering discovered `tsconfig.json`, `jsconfig.json`, `package.json`, `oh-package.json5`, plus any locally resolved `extends` parent configs (`tsconfig.base.json`, etc.).
  - `tsConfigs`: normalized `{ scopeDir, kind, baseUrl?, paths }` rules.
  - `packageExports`: normalized local `{ dir, name, exports }` rules (relative `./` targets only, ignoring `node_modules`).
  - `ohPackages`: normalized `{ scopeDir, name?, main?, dependencies }` rules (local `file:` / `./` / `../` targets only, ignoring `oh_modules` and `@ohos.*`/`@kit.*` SDK namespaces).
- **Incremental invalidation**:
  - Unchanged source + unchanged config `mtimeMs` (`indexesEqual` checks `resolution` equality) results in zero cache rewrites.
  - Modifying, adding, or deleting any tracked config (including `extends` parent configs) invalidates `resolution`, updates the cache, and triggers live watcher refreshes in `RepoContextManager`.

### 3.2 Phase M2 Sub-features & Design Notes

1. **P1a — Verification Command Leads (`src/test-leads.ts` + `src/review-brief.ts`)**:
   - Inspect nearest manifest for each candidate test file (`package.json` scripts/devDependencies for `vitest` / `jest`, `pyproject.toml` for `pytest`, `go.mod` for `go test`, `Cargo.toml` for `cargo test`) to derive the narrowest deterministic `commandLead` (e.g. `pnpm vitest run tests/foo.spec.ts`, `pytest tests/test_foo.py`, `go test ./pkg/...`, `cargo test ...`).
   - Strictly static: `verification` remains `'not-run'`, and no test command is ever spawned.
   - When no runner can be deterministically identified, leave `commandLead` omitted and record `verification-command-unavailable` in `gaps`.
   - Under tight `budgetChars`, strip optional `commandLead` fields before dropping candidate tests, relations, or source excerpts.

2. **P1b — Change Cycle Warning (`src/change-context.ts` + `src/review-brief.ts`)**:
   - Reuse `findCycles(index)` from `src/health.ts` (Tarjan SCC) to check whether any changed file (or direct import dependent / impact subgraph node) belongs to a strongly connected component of size > 1.
   - Surface deterministic `cycle-warning` entries in `ReviewBrief` (`warnings` / `gaps` / rendered output) without breaking `text` or `xray` contracts.

3. **P2 — Monorepo Cross-package Impact (`src/workspace.ts` + `src/review-brief.ts` + `src/impact-xray.ts`)**:
   - Parse `pnpm-workspace.yaml` (workspace globs/dirs), root `package.json#workspaces`, `Cargo.toml` `[workspace].members`, `go.work` `use` directives, and HarmonyOS `build-profile.json5` `modules[].srcPath` to build a longest-prefix `dirPrefix -> packageName` table.
   - Aggregate affected symbols/files/dependents by package in `ReviewBrief` (`Cross-package impact`) and `Impact X-Ray`, honoring `REVIEW_LIMITS` and `XRAY_LIMITS.metadataBytes`.
