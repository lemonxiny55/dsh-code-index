# M2：Context Evidence Summary

2026-11-05，Asia/Shanghai。基于 `52da07c`，开发分支仍为
`codex/reliable-context-v0.12.0`。本轮只实现 Evidence Summary；正式版本仍为 0.11.2。

## 用户可见变化

`code_context` 默认文本增加确定性证据摘要，`outputFormat: "pack"` 在原 version 1
DTO 上增加可选 `evidence`。旧字段、工具名称、参数和默认字符串返回均不变。

- **索引范围**：分别统计 parsed、partial、failed、unknown。缺少旧版诊断元数据时
  不假定 parsed。明确这些数量仅描述当前已索引文件，未扫描文件没有被评估。
  partial/failed 最多列出三处真实文件/诊断行和已知 reason；其余用
  `diagnosticsOmitted` 标记并指向 `code_index`，不编造错误位置。
- **关系**：保留 exact / import-scoped / name-only。统计的是选中的 call/import/path
  呈现项，不是唯一图边、概率或运行影响；测试线索的关联等级单列，不混入该计数。
  `callers.zero` 仅来自实际查询过的当前声明与已有 incoming 图，明确“当前索引和静态
  解析范围未发现”，不等于没有调用者。无法解析的已索引调用点保留位置，目标未知，
  不能判成外部调用。`code_refs` 的原 `(external)` 误导标签同步替换为 unresolved。
- **测试**：候选数只统计最终保留的测试文件，`verification: "not-run"`。
  它表示本次静态分析没有运行测试；import、命名约定、exact 都不能证明覆盖或通过。
- **缺口**：使用 kind / code / source，必要时附 file / side，区分 not-found、
  unavailable、budget、index-incomplete，以及额外的 selection-limit。
  任务摘要缩短、maxFiles、实际未覆盖的源码窗口分别说明，不再一律称预算裁剪。
  reader 拒绝读取只说明证据不可用，不猜测一定发生了编辑；Git 分析失败也不当作
  “成功查询了一个空 diff”。

`code_change_context` 使用同一摘要模型和候选测试说明。其 `evidence.basis` 为
`change-analysis`；Context Pack 为 `context-pack`。Impact X-Ray 只增加同一可选分析
元数据，并在原 Gaps 视图复用范围说明；投影数量仍看现有 bounds，没有新 UI 或图关系。

## 预算与兼容

默认 5000、300～20000 边界和 text / JSON 双重字符上限保持不变。
摘要在同一预算内计费，不能在渲染后额外追加。优先保留 primary 源码、明确声明、
直接邻域及任务点名文件的 caller；可移除低优先级线索，随后缩减诊断/位置列表。
仍放不下时省略可选 `evidence`，尽可能用 `budget: summary omitted` 说明。
不能把字段缺省或明细 omitted 当作“没有问题”或“没有调用者”。极长 root 加极小预算时，
身份、重要缺口优先，提示本身也受同一个硬上限约束。

完整历史 T1/T2 的 8000 字符 Pack 已接近占满，仍会省略结构化摘要，保留关键源码、
既有索引警告及预算提示；T3 可以让低优先级跨层线索腾出摘要位置，核心五个实现仍保留。
本轮没有为了强制每包都含摘要而提高预算或牺牲既有六例源码契约。

`budget.truncated` 保留兼容含义；文本改为 bounded output，实际原因看 evidence/gaps。
`code_change_context` 保持原固定 section renderer 的最小预算规则：低于可保留骨架的
maxChars 会明确拒绝，新增摘要会先退让，不通过越界输出满足小预算。

## 实际输出示例

由 `tests/evidence-summary.spec.ts` 的五文件真实临时仓库，经实际 `code_context.execute`
分别取得默认文本和 pack，并断言文本等于 `renderContextPack(pack)`。
不是模型回答或真实用户项目；示例中的临时 root 已清理，输入源码保存在测试中。

完整示例：[`context-example.txt`](m2/context-example.txt)、[`pack-example.json`](m2/pack-example.json)、
[`change-example.txt`](m2/change-example.txt)。本次默认预算 5000，文本 **982**、JSON **1179** 字符。
示例完整 JSON 文件使用缩进展示；预算针对紧凑 `JSON.stringify(pack)`，不计外加展示空白。

文本中的摘要原文：

```text
Evidence (indexed static scope; unscanned files not assessed):
Index: 5 parsed, 0 partial, 0 failed, 0 unknown.
Selected relationship items: exact 0, import-scoped 0, name-only 0.
Tests: 1 candidate(s), not run; not verified coverage.
0 callers for idle (src/core.ts:4): none found in current index/static resolution; not proof of no callers.
```

对应 JSON 摘录（其余原有字段见完整示例）：

```json
{
  "scope": "indexed-static-only",
  "basis": "context-pack",
  "index": { "parsed": 5, "partial": 0, "failed": 0, "unknown": 0 },
  "relationships": { "exact": 0, "import-scoped": 0, "name-only": 0 },
  "tests": { "candidates": 1, "verification": "not-run" },
  "callers": {
    "checkedSymbols": 1,
    "zero": [{ "file": "src/core.ts", "line": 4, "name": "idle" }]
  }
}
```

该测试文件 import 的是同一源码文件中的 target，并没有测试 idle。
保留它只能说明存在文件级测试线索，恰好展示为什么不能将关联解释成覆盖。

## 来源与限制

`src/evidence-summary.ts` 只读取现有 `IndexedFile.diagnostic`、已有 ReferenceGraph、
实际选中呈现项及检测条件，不扫描文件系统、不调用 parser、不重建索引、不新增解析边。
Pack 还复用 orchestration 已构建的 graph。源码读取继续使用现有 reader 安全检查。
已全部提供的测试文件窗口、或通过去重分段已完整覆盖的声明，不再误报为源码缺口。

parsed 不代表全语言语义完整；unknown 不代表 parse failed。SDK、动态派发、未索引文件、
索引外调用和 Rust 外部函数不能从零计数推导。`unresolved.sites` 是已提取却没有图目标
的调用点，既不是外部调用清单，也不包括 parser 根本未提取到的调用。
候选测试没有被本工具执行，用户此前可能运行过的测试也不会被自动纳入证据。
